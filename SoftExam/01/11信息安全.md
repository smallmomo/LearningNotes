
# 1.加密算法

典型的对称加密算法：DES，3DES，AES等。  
典型的非对称加密算法：RSA，ECC等。
典型的摘要算法：SHA，MD5等。

可以把这三类算法理解成：

* **对称加密**：双方用“同一把钥匙”
* **非对称加密**：一把锁（公钥）+ 一把钥匙（私钥）
* **摘要算法**：不是加密，而是“生成指纹”

它们在实际系统里通常会组合使用，比如 HTTPS、微信支付、登录认证、JWT 等。

---

## 一、对称加密算法（Symmetric Encryption）

### 核心特点

加密和解密使用 **同一个密钥**。

```text
明文 --(密钥K)--> 密文
密文 --(密钥K)--> 明文
```

例如：

```text
原文：hello
密钥：123456

加密后：A8F91C...
```

解密时仍然需要 `123456`。

---

### 优点

#### 1）速度快

适合：

* 大文件
* 大数据量
* 高频通信

所以数据库字段加密、文件加密、HTTPS 数据传输最终都大量使用对称加密。

---

### 缺点

#### 1）密钥分发困难

问题：

> 如何安全地把“同一个密钥”告诉对方？

如果密钥被偷：

```text
攻击者 = 能解密所有数据
```

---

### 常见算法

| 算法   | 说明       |
| ---- | -------- |
| DES  | 老算法，已不安全 |
| 3DES | DES 增强版  |
| AES  | 现在最主流    |
| SM4  | 国密对称算法   |
| RC4  | 已不推荐     |

---

### AES 示例

#### 加密

```java
Cipher cipher = Cipher.getInstance("AES");
cipher.init(Cipher.ENCRYPT_MODE, key);
```

#### 解密

```java
cipher.init(Cipher.DECRYPT_MODE, key);
```

---

### 应用场景

#### HTTPS

真正传输数据时：

```text
HTTP内容 -> AES加密
```

因为 AES 快。

---

#### 数据库存储敏感字段

例如：

* 手机号
* 身份证
* 银行卡

---

## 二、非对称加密算法（Asymmetric Encryption）

### 核心特点

使用：

* 公钥（Public Key）
* 私钥（Private Key）

两把钥匙不同。

---

## 核心原理

### 1）公钥加密，私钥解密

```text
公钥 -> 所有人可见
私钥 -> 自己保存
```

流程：

```text
明文 --公钥--> 密文
密文 --私钥--> 明文
```

只有私钥拥有者能解密。

---

### 2）私钥签名，公钥验签

```text
数据 + 私钥 -> 签名
签名 + 公钥 -> 验证
```

用于：

* 防篡改
* 身份认证

---

## 优点

### 1）解决密钥分发问题

公钥公开即可。

---

## 缺点

### 1）速度慢

远慢于 AES。

所以：

```text
非对称加密 ≠ 适合大量数据
```

---

## 常见算法

| 算法  | 说明       |
| --- | -------- |
| RSA | 最经典      |
| DSA | 数字签名     |
| ECC | 椭圆曲线，更高效 |
| SM2 | 国密非对称算法  |

---

## RSA 举例

### 公钥加密

```text
客户端用服务器公钥加密
```

### 私钥解密

```text
服务器私钥解密
```

---

## 应用场景

### HTTPS 握手

HTTPS 里：

```text
RSA/ECC：
    用来交换 AES 密钥

AES：
    用来真正传输数据
```

因为：

```text
RSA 安全但慢
AES 快
```

所以两者组合。

---

## 三、摘要算法（Hash / Digest）

### 核心特点

摘要不是“加密”。

它是：

```text
输入任意数据
↓
生成固定长度“指纹”
```

例如：

```text
hello
↓
5d41402abc4b2a76...
```

---

## 特点

### 1）不可逆

无法从摘要反推原文。

```text
hash("hello") = xxx
但无法反推 hello
```

---

### 2）输入变化一点点，结果完全不同

```text
hello
↓
abc123

hello!
↓
9ff888
```

---

### 3）长度固定

无论原文多长：

* MD5：128位
* SHA256：256位

---

## 常见摘要算法

| 算法     | 说明     |
| ------ | ------ |
| MD5    | 已不安全   |
| SHA1   | 已不安全   |
| SHA256 | 常用     |
| SHA512 | 更强     |
| SM3    | 国密摘要算法 |

---

## 应用场景

### 1）密码存储

错误做法：

```text
数据库存明文密码
```

正确做法：

```text
存 hash(password)
```

登录时：

```text
用户输入密码
→ hash
→ 比较数据库hash
```

---

### 2）文件完整性校验

下载文件：

```text
xxx.zip
MD5: 8a7b...
```

下载后重新计算 MD5：

* 一样 → 文件没损坏
* 不一样 → 文件被篡改

---

### 3）数字签名

签名时：

```text
不是对整个文件签名
而是对摘要签名
```

原因：

```text
大文件直接签名太慢
```

---

## 四、三者区别（核心）

| 类型    | 是否可逆 | 密钥    | 作用      |
| ----- | ---- | ----- | ------- |
| 对称加密  | 可逆   | 同一个   | 数据加密    |
| 非对称加密 | 可逆   | 公钥+私钥 | 密钥交换、签名 |
| 摘要算法  | 不可逆  | 无     | 数据指纹    |

---

## 五、HTTPS 里的组合（非常经典）

HTTPS 同时用了三种：

---

### 第一步：摘要算法

服务器证书：

```text
CA对证书做摘要
```

用于校验证书。

---

### 第二步：非对称加密

客户端：

```text
用服务器公钥加密 AES 密钥
```

发送给服务器。

---

### 第三步：对称加密

后续通信：

```text
全部使用 AES
```

因为速度快。

---

## 六、一句话理解

### 对称加密

```text
同一把钥匙开锁
```

---

### 非对称加密

```text
公开锁，自己留钥匙
```

---

### 摘要算法

```text
生成不可逆的数据指纹
```
